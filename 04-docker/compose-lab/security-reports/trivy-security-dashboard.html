5. How to interpret these results

Severity is a vulnerability classification, not proof that an attacker can exploit your running app. Fix available means the report contains a fixed version; upgrading still requires compatibility testing. No fix listed means the scan has not identified a fixed version, not necessarily that no fix exists anywhere.

OS packages come from the base container image. Language packages include Python dependencies. Multiple package records may refer to the same CVE, so counts represent vulnerability records, not necessarily unique security issues.

Recommended workflow: prioritize Critical/High findings with fixes; update your Docker base image and Python dependencies; rebuild with docker build --pull --no-cache; rescan; compare; document remaining risks.
